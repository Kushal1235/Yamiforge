
YAMIFORGE
Product Requirements & Build Plan
Train. Track. Forge.
A phased plan for an AI-assisted fitness and workout tracking application
Working specification • Version 1.0 • October 2026

1. Product Vision
YamiForge is a modern, responsive fitness application that helps users choose a training goal, understand different training styles, build a suitable workout split, learn correct exercise technique, track completed workouts, and eventually create AI-assisted anime-themed workout artwork.
Product principles
Training categories, weekly splits, exercise instructions, workout prescriptions, and workout history must be distinct concepts.
Make the first version useful without requiring an AI service or backend.
Use a polished dark interface with restrained purple accents, clear typography, responsive layouts, and purposeful animations.
Keep fitness data and recommendations understandable; do not present generated content as professional medical advice.
Build incrementally with testable features and a stable release branch.

4. Exercise Library
The Exercise Library is a core feature. It explains how to perform each exercise and what it trains. It is separate from the workout plan and workout tracker.
4.1 Exercise detail page
Exercise name and demonstration: short video, animation, or sequence of images.
Primary and secondary muscles, with a clear muscle map where available.
Required equipment and difficulty level: beginner, intermediate, or advanced.
Step-by-step technique instructions and breathing guidance.
Common mistakes, safety notes, and exercise alternatives.
Sets, reps, and rest should be prescribed by the workout plan rather than hard-coded into the exercise definition.
Tracking controls should record the user's completed sets, reps, and load.

5. Workout Planning and Tracking
5.1 Workout plan builder
Let users select training style, goal, experience level, available equipment, weekly frequency, and preferred split.
Allow users to view and adjust the proposed weekly schedule before saving.
Support exercise ordering, sets, rep ranges, rest time, and optional notes.
Include rest/recovery days and avoid implying every user should train six or seven days per week.
Make generated plans editable and explain that plans are general fitness guidance, not medical advice.
5.2 Workout tracker
Mark exercises and individual sets as complete.
Record load/weight, reps, completion status, and optional notes.
Show workout duration and a history of completed sessions.
Later provide progress charts, personal records, consistency indicators, and exercise history.
5.3 Keep the concepts separate

6. AI Anime Workout Poster Generator
A planned differentiating feature: users can select a workout split and choose an anime character or upload a reference image, then create a themed workout poster. Character use and reference-image processing must respect the chosen image provider's policies and applicable rights.
6.1 Proposed user flow
Choose a workout split or a specific workout day.
Choose a character/theme or upload a reference image.
Select a visual style, color palette, and poster format.
Generate the artwork.
Render workout text—exercise names, sets, reps, and day title—in a separate UI/text layer for accuracy.
Preview, regenerate, save, or share the finished poster.

7. UI/UX Requirements
Modern, polished, anime-inspired visual identity; dark theme with restrained purple accents.
Responsive layouts for mobile, tablet, and desktop.
Clear navigation for Dashboard, Workout Plans, Exercise Library, Workout Tracking, Progress, and Settings.
Useful loading, empty, error, and success states.
Accessible contrast, keyboard focus, labels, and touch-friendly controls.

Keep poster text legible and editable independently of the generated artwork.

9. Architecture and Code Quality
Use standalone Angular components and route-based lazy loading for major feature areas.
Keep feature code organized by domain (dashboard, plans, exercises, tracking, progress, poster studio).
Use reusable UI components and typed interfaces; keep data access separate from presentation.
Begin with local/mock data and services; later replace implementations with API-backed services.
Use environment configuration for non-secret settings; keep private API keys on the server.
Add tests as each feature is implemented; check build, lint, and test results before merging.
Decide which routes need SSR and ensure browser-only APIs are guarded where required.
10. Git Workflow and Delivery
Intended workflow: use main for active development and master as the stable release branch, as requested. Before changing branch names or merging, verify the repository's actual current branch and remote state.
Create small, feature-focused commits.
Run build and relevant tests locally.
Open a pull request or review changes before promoting them to the stable branch.
Use GitHub Actions to automate checks; only deploy after required checks pass.
Document setup commands, environment variables, and release steps in the repository.

13. Acceptance Criteria for the First Useful Release
Users can navigate a responsive YamiForge interface on mobile and desktop.
Users can understand the difference between training styles and workout splits.
Users can select a training goal and split and view an editable sample weekly plan.
Users can browse an Exercise Library and open detailed exercise instructions.
Users can log a basic workout and review a session history using mock/local data.
The app builds successfully and has tests for its most important flows.
AI image generation is optional and does not block core workout features.
Appendix A — Example Feature Flow
Dashboard → Set goal → Select Bodybuilding → Choose Muscle Gain → Select Push/Pull/Legs → Choose training frequency → Review weekly plan → Open Bench Press in Exercise Library → Review muscles and technique → Start workout → Log sets/reps/load → Finish session → Review history → Optionally create an anime-themed workout poster.
Appendix B — Product Scope Guardrails
Do not mix training style, split, individual exercise, and workout session into one data model.
Do not rely on AI-generated text inside images for accurate exercise names, sets, or reps.
Do not expose image provider credentials in Angular code.
Do not use unlicensed media or assume every named character can be used without restrictions.
Do not delay the core exercise library and tracker while implementing advanced AI features.
